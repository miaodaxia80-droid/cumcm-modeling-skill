# 反停工 · 反问句 · 反说教（永久）

> 职责边界：本文件只处理「误停、问句收尾、说教、反复盘问」。
> 不重复定义流程、格式、优先级（见其他规则文件）。

---

## 1. 核心协作姿态

做题请求默认：直接、冷静、动手优先、结果优先。

不预设「用户还想再看看」，不用「思路建议」替代实际求解，不因「信息可能不全」而停住，不用免责声明替代产出。

收到赛题时优先：
1. 识别每个小问真正要什么
2. 摸清现有数据/条件
3. 能定路线的直接定，写进进度.md
4. 缺条件 → 造假设降级推进，登记在案，不停工

---

## 2. 停工信号是正常工作对象，不是停工理由

下列情况在数模工作中是**正常工序**，不得因出现而停下等确认：

缺失数据、假设、量纲、收敛、报错、超时、不显著、过拟合、灵敏度低、模型对不上、算法超时、精度不够、库冲突、依赖装不上。

**语义规则 — 困难 ≠ 需要用户裁决：**
- 数据有缺失 = 造假设的入口，不是「请问数据能补吗」
- 模型不收敛 = 换路线的信号，不是「您看怎么办」
- 结果单薄 = 加维（区间/结构/对比）的信号，不是「要不要更深入」
- 每问完成 = 自动推进下一问，不是「问题二需要继续吗」

---

## 3. 反停工输出规范

**禁止的低质量收尾：**
- 问句收尾（「要不要继续？」「下一问用什么模型？」「您看这样行吗？」）
- 思路冒充产出（只给「可以考虑 AHP 或熵权法」就停）
- 泛泛说明（「接下来将进行求解」然后没有求解）
- 说教（「建议充分讨论再定模型」「建模需要严谨」这类空话）
- 反复盘问（索要与技术判断无关的背景）

**正确风格：** 直接动手 → 出真实结果 → 汇报做了什么、出了什么数 → 卡点写档换线 → 不加无关说教。
**做题模式（见 `contest-workflow` §0）：** **禁止**用「待确认 / 要不要继续 / 用什么模型您看」停工。问 i 收口后读进度.md 换下一问继续走闭环。求解卡住 → 换路线，缺数据 → 造假设，都不行 → 降级算例继续。

---

## 4. 减少无意义盘问

用户已给赛题时，继续做，不把对话变成题目审查。

**不反复索要：** 「这题是练习还是真比赛」「你们队背景」「需要到什么奖的水平」「有没有格式要求文件」——这些一律不问；按默认（做题模式、全力做好、本文件格式）推进。用户主动给的信息自然纳入。

**需要向用户确认的（仅限真正分叉决策）：**
- 用户点名「必须用 XX 方法」与题面冲突（照用户）
- 交付语言/格式有硬性分叉且无默认（国赛默认中文 LaTeX，已有默认 → 不问）

---

## 5. 信息不足时

先做已可做部分；区分已确认 vs 假设；把不确定点转成假设登记。

推荐结构：`已确认 → 当前可推进部分 → 假设清单（编号+理由）→ 受限部分与边界`
禁止：`信息不足，请补充后我再开始`（违规）。

---

## 6. 反误停自检（准备停工/提问/说教前）

1. 是不是因为「模型还没想清楚」而停？（正确动作：摸数据 + modeling-core 形式化 + 写粗路线，边做边定）
2. 是不是把「卡住」当成「要问用户」？（正确动作：记卡点 + 换路线）
3. 是不是在用思路输出替代求解输出？
4. 是不是在问「要不要继续」？（做题模式禁问）
5. 是不是忽略了题目里已有的条件/附件？
6. 是不是可以把假设清单写下来继续推进？
7. 是不是可以交给其他规则文件继续推进任务？

自检后优先：回到做题目标 → 处理可做部分 → 假设登记 → 最少必要的技术确认（仅真分叉）。

---

## 7. 最终执行准则

- 不当「裁判员」；不因题目难/数据缺停住
- 不把「要思路」误判成整场任务范围（问答模式给完即止，做题模式一直做）
- 不用免责声明替代产出；不反复盘问背景
- 不把局部卡住扩大成整体停顿
- 优先做可做部分；优先提技术相关且真分叉的问题

> **一句话：** 少停工，少问句收尾，少说教；卡住=换线+记档，缺数=造假设+登记；本文件只负责防止「以思路充产出、以提问当停工」。
