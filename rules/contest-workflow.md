# 竞赛主流程 · Phase 0～6（永久）

> **一律增强，不限制死**（与 `skill-as-boost` 同精神）。
> **用户不应靠「催」才发现空转** — Agent 必须自检纠偏，禁止用「写了大纲/列了思路」装忙。
> **一问闭环** 与 `modeling-value.md` 一致，本文件不缩标准。
> **反停工：用户未主动叫停则一直推进；禁止中途问「要不要继续」。**
> **一问闭环（2026-09-11 立）：所有问一律「拆解 → 建模 → 真实出数 → 出图 → 进草稿」完成后才算收口；禁止先规划完所有问再统一求解。**
> **两级设计（2026-09-11 升级）：全卷粗路线（目标/输入/输出/依赖/候选模型）Phase 2 一次做完；单问详细建模只在轮到该问时做。两级粒度不同，不冲突。**
> **两级检验：单问收口前做「最低验证」（sanity + 独立验证证据），跨情景灵敏度/稳健性归 Phase 4 全文检验。**
> **收口唯一标准 = §2 收口表**；其它文件提到「收口/闭环/完成」一律指它，禁止另立标准。

## 0. 先判模式

| 用户指令 | 模式 | 行为摘要 |
|----------|------|----------|
| 给了完整赛题（题面 + 附件数据），要完成 | **做题模式（默认）** | 建任务夹 → Phase 0～6 一题到底；逐问闭环 |
| 三道题全给了、没指定做哪道 | **做题模式 + 选题决策（§0.1）** | 先按信号选一题，再全流程；说明选择理由后**立刻开做**，不问用户 |
| 只给部分题面 / 没有附件数据 | **做题模式（降级）** | 按 §1 降级口径：缺数据能造假设就造，造不了的部分写清边界；**禁止**以缺数据为由停工 |
| 说「帮我备赛 / 准备工具 / 出模板」 | **备赛模式** | 工具链 + 模板 + 真题清单 + 方法论；不硬编论文 |
| 「这道题用什么模型？」（只要思路） | **问答模式** | 短答给出候选模型 + 理由，**不落论文**；答完即止 |
| 「帮我评审/看看这篇数模论文」 | **审稿模式** | 按 `paper-format` + `result-check` + `abstract-writing` 清单逐项评审给意见；不重做题、不改原文 |

原则：**给了题就做题，禁止只给思路不动手。** 当次指令优先（当场说「只要思路 / 先别写论文」→ 压过默认）。

### 0.1 选题决策（三题全给、无指定时）

决策维度：数据附件是否齐全 / 模型确定性 / Agent 能力面。

| 信号 | 判断 |
|------|------|
| C 题附件完整（CSV/Excel 多表），问句以「数据分析/评价/预测」为主 | **首选 C**：数据题闭环最稳，每问都能落到真实数值与图 |
| A/B 题附件是物理参数/几何参数，机理清楚（方程可写出） | 次选：diff/phys 模块能闭环则可选，否则仍回 C |
| B 题是离散优化/调度/排班 | 有明确约束清单且数据小 → op 模块可解；约束含糊谨慎 |
| 三题都无法闭环（附件缺、问题含糊） | 选附件最完整的那道；缺的部分造假设并写明 |

**禁止**：为「题目难度高显得厉害」选机理题而数据题闲置——评委只看结果，先保证闭环完成度。用户点名题号 → 照办（当次指令压过默认）。

### 0.2 协作裁定（压过「等确认」）

| 语境 | 行为 |
|------|------|
| 做题模式（默认） | **不停、不问继续**；缺数据 → 造假设降级推进，边做边记 |
| 备赛 / 问答 | 清单尽或按需给；给完即止 |
| 真缺唯一技术前提（如必须的第三方求解器装不上）且无法降级 | 极短报障后仍做能做的问；**禁止**用提问当停工理由 |

## 1. 做题模式：Phase 0～2（开局，30 分钟内必落盘）

### 1.0a 数据获取与保真闸（2026-09-11 实测新增 · 官方附件不在手时第一步）

流程假设「附件在手」，但实际拿到真题往往只有题面文本/PDF 甚至截图。**先拿官方原始包，再开始任何建模**：

| 步骤 | 动作 |
|------|------|
| 1 | 官网「赛题与评奖 → 历年竞赛赛题」→ 对应年份页 → 题目 zip（内含全部题面 PDF + 全部附件 + result 模板）；落 `题目/` **只读** |
| 2 | 题面 PDF 用文本提取（pypdf）后**逐条登记约束**（每条一行进 进度.md），禁止凭记忆或二手博客定约束——历年题目约束条款不同（2023C 的 1.5/0.5 倍扩产限制在 2024C 就不存在） |
| 3 | 用户只给了二手题面/截图 → 必须找到官方版本核对条款；对不上以官方为准并在进度.md 记差异 |
| 4 | 附件 Excel 按知识库 `data-cleaning.md`「官方 Excel 三闸」处理（合并单元格 ffill / 全表 strip / 字段名冲突） |

保真闸验收：题面约束清单（编号）+ 附件摸底数字（行数/列数/总量级）已落 `进度.md`，清洗数据可一键复跑。

**数据口径三级登记（进 `进度.md`，每问标注）：**

| 口径 | 定义 | 处置 |
|------|------|------|
| `official` | 官方题面 + 官方附件 | 正常推进；结果可作正式结论 |
| `assumption` | 题面允许估计的参数 / 二手题面已核对条款 / 附件可推导的量 | 造假设登记（编号+理由+范围），结果可作正式结论，正文标注假设来源 |
| `synthetic-demo` | 人为构造的演示数据 | **只用于验证代码与模型结构**；结果文件名标 `demo_` 前缀，禁止当正式题目结论写进论文 |

官方包拿得到 → 必须按上表步骤 1~4 拿；**拿不到 → 不停工**：按当前最高可得口径继续（二手题面 + `assumption`），差异登记进 `进度.md`；全缺数据 → `synthetic-demo` 先跑通结构，论文对应问如实写「演示性算例」。本闸管的是「结果能不能当正式结论」，不管「要不要停工」。

### 1.0 一张图（起手必过）

```
给题
  ├─ 桌面有 {题号}_数模竞赛 且进度未终态？
  │     是 → 续做：读 进度.md + 结果清单 + 论文/草稿；跳过已收口的问；从最近未收口处接
  │     否 → 新开：建任务夹（task-folder）→ 落 进度.md
  │
  ├─ 知识库有对应 `*数模经验.md`？有才开，没有不算缺
  │     有 → 和短表并行打开；专篇=该题坑位口径，不替代流程
  │
  ├─ Phase 1 读题拆题：
  │     题号类型 → 逐问拆成「输入→模型→输出」清单 → 附件数据摸底（几列、几行、缺什么）
  │
  ├─ Phase 2 路线设计：
  │     每问定「目标/输入/输出/依赖/候选模型」粗路线，写进 进度.md；对得上短表 → 打开对应模块
  │
  └─ Phase 3～6：逐问闭环 → 检验 → 摘要成文 → 终检提交包
```

### 1.1 Phase 1 · 读题拆题（硬 · 防空扫）

**拆题产出（写进 `进度.md`，禁止空着开算）：**

| 项 | 要求 |
|----|------|
| 题号与类型 | A 机理型 / B 离散优化型 / C 数据分析型 / D、E 专科题；判断依据写一句 |
| 问题清单 | 每个小问一行：问什么、输入是什么（题面数据/附件哪列/前问输出）、要求输出什么（数值/排名/方案/图） |
| 数据摸底 | 附件几张表、每表行列数、关键字段、缺失/异常一眼登记；**先读数据再选模型** |
| 约束与假设候选 | 题面明示的约束、隐含的常识约束（各一列，建模期转化为正式假设） |
| 问间依赖 | 哪问用到前问输出 → 决定求解顺序（被依赖的先做） |

**禁止**：不摸数据就拍模型；把「问题重述」当拆题；只拆问题一就开始算问题一不看全卷。

### 1.2 Phase 2 · 路线设计（两级设计）

路线分两级，粒度不同、时机不同，**不与一问闭环冲突**：

| 级 | 时机 | 产出（写进 `进度.md`） |
|----|------|------------------------|
| **全卷粗路线** | Phase 2 一次做完 | 每问一行：目标（要什么输出）、输入（附件哪表/前问哪个结果）、依赖（被谁依赖→求解顺序）、候选模型（1~2 个备选名）。**只到候选名为止** |
| **单问详细设计** | 轮到该问时才做 | 该问的变量定义、假设、公式化、算法、独立验证证据选型（`result-check.md` §三）；做完即进 §2 求解闭环 |

「先读全卷」与「禁止规划完所有问再统一求解」由此各管各的：粗路线管顺序与依赖，详细建模只属于当前问。开算前每问先过 `知识库/modeling-core.md` 形式化（问题五分类 + 最小模型说明表）。

**选型速查（细节进对应模块）：**

| 问句信号 | 主模型首选 |
|----------|-----------|
| 最优分配/利润/排班 | LP/MIP（`op-models.md`） |
| 方案评价/排名 | 权重来源判定 → TOPSIS/适当聚合（`eval-models.md`） |
| 时间序列预测 | ARIMA / 组合预测（`predict-models.md`） |
| 截面数据预测/因子分析 | 多元回归 + 显著性（`stat-models.md`） |
| 增长/传染/衰减 | 微分方程（`diff-models.md`） |
| 路径/选址 | 最短路/设施选址（`graph-models.md`） |
| 大样本分类回归 | 随机森林/XGBoost（`ml-models.md`） |
| 随机到达/资源争用 | 蒙特卡洛 / M/M/c 排队（`sim-models.md`） |
| 机理 + 数值计算（A 题常见） | 数值建模链（`numerical-models.md`） |
| 信号/频谱数据 | 信号处理链（`signal-models.md`） |
| 空间/地理数据 | 空间建模链（`spatial-models.md`） |
| 控制/决策序列 | 控制与动态规划（`control-models.md`） |

**禁止**：路线只写「建立数学模型」这种空名；粗路线阶段就把某问公式全推完（那是单问详细设计的活）；跳过 `modeling-core.md` 形式化直接按关键词套模型。

## 2. 一问闭环（硬 · 全部问一律）

> **所有问一律这样，没有例外。**
> **禁止**把全部问的模型先「设计完」再回头统一编码——那是假进度。

```
取一个未收口的问 i（被依赖的问优先）
  → 建 i 的假设（转正式假设，写符号表）
  → 建 i 的主模型（公式化，符号一致）
  → 编码实现并真实运行 → 结果文件落盘 结果/q{i}/
  → 由真实结果出图 → 图落盘 结果/q{i}/figs/
  → 该问求解正文写进 论文/草稿.md（含结果数字 + 图引用）
  → 问 i 标收口 → 更新 进度.md → 立刻取下一问
```

**「收口」是什么 / 不是什么：**

| 是 | 不是 |
|----|------|
| 该问出了真实数值结果（结果文件在 `结果/`）+ 至少一张真数据图 + 求解正文进草稿 | 模型公式写在草稿里但代码没跑 |
| 独立验证证据 ≥1 项（或 N/A+原因）且口径已登记（official/assumption/demo） | 代码跑通但没把数字写进正文 |
| 求解失败但已记录失败原因 + 换了路线再试一轮 | 只答了题面问的第一小项 |
| 该问按题面要求输出了排名/方案/数值全部小项 | 假设没落假设清单就用了 |
| 数据不完整时：造假设→跑通→结果标注假设与口径 | |

**「收口」唯一标准 = 本表。** 其它文件（SKILL、modeling-value、摘要闸、心跳自检）提到「收口/闭环/完成」一律指本表，禁止另立标准。

**禁止：**

| 禁止 | 说明 |
|------|------|
| 批量假进度 | 先把 3 问的模型全写成公式再统一求解 |
| 空转式换问 | 问 i 没收口、没记卡点，就跳去做问 j 纯磨排版 |
| 结果不落盘 | 数字只在对话里、不在 `结果/` 文件里 |

### 2.1 降级口径（缺数据 / 装不上 / 不收敛）

| 场景 | 做法 |
|------|------|
| 附件数据缺失部分字段 | 可造的（比例、系数）造假设并登记假设清单；不可造的该子项标注「受数据限制，按假设 X 计算」 |
| 求解器/库装不上 | 换等价开源库（`solver-toolkit.md` 对照表）；再不行换简化模型；都不行该问降级为小规模算例并写明 |
| 模型不收敛 / 跑不完 | 查量纲、改初值、放宽约束、换启发式（`op-models.md` 求解失败处置） |
| 题面信息不足以定模型 | 写出两种可行解释各跑一版，正文以对比呈现，不问用户 |

有前端吗？——数模没有「前端」，但有等价物：**图表就是前端**。数据摸底完先出一两张探查图（分布/散点/时序），既喂模型选择又攒论文素材，**这一步不算空转**。

## 3. 实战节拍（比赛实况 · 有截止时间才启用）

比赛全程约 72～74 小时（以当年通知为准）。练习模式跳过本节，照 Phase 推进即可。

| 时段 | 里程碑 | 硬闸 |
|------|--------|------|
| 0～2h | 读全卷三题 → 按选题决策定题 → 拆题落盘 | 超时未定题 → 按 §0.1 信号强制选 C |
| 2～6h | 数据摸底 + 每问路线设计 + 文献检索（真实文献） | 路线表落盘 |
| 6～24h | 问题一、问题二闭环 | 每问出真实数字 |
| 24～40h | 问题三、四闭环 + 各问独立验证证据 | 中期自查：图是不是真数据 |
| 40～54h | 检验（灵敏度/误差/稳健性）+ 补图 | result-check 勾完 |
| 54～64h | 正文整合 + 摘要初稿 → 摘要打磨（至少两轮） | 摘要含每问数字 |
| 64～70h | 全文终检：数字一致性、格式、红线逐条过 | 红线清单全勾 |
| 70h～ | 生成 PDF + MD5 + 支撑材料包，提交 | 提前量 ≥2h，**禁止**卡截止线改内容 |

**压缩/断点续跑后：** 优先读 `进度.md` + `结果/` 清单 + `论文/草稿.md`，从最近未收口处接着干；禁止压缩后凭会话记忆拍模型。

## 4. 单问主路径（Phase 3 细节）

进问口令（细节往下翻）：说清这问要什么 → 假设转正式 → 模型公式化 → 编码真出数 → 图 → 进草稿。

### 4.0 进问先说清这问（硬 · 防空算）

草稿里先 3～5 行写清（不准写成作文）：

- 这问要输出什么（数值表 / 排名 / 方案 / 判定）
- 输入是什么（附件哪张表 / 前问哪个结果）
- 钱与约束落在哪几个量（目标函数、约束对象）
- 主模型是什么、为什么它配这问（一句）

说不清就先摸数据补，不许空着开写公式。看到「灵敏度」「稳健性」「不同方案对比」→ 当本问要求项跟，不是成文期才想起。

### 4.1 先建模型骨架（公式化）

**有数据：** 打开附件 → 摸列含义与量纲 → 把该问写成「决策变量 / 目标 / 约束」或「输入 → 映射 → 输出」的公式形态 → 写进草稿。

公式形态里就顺手登记：

| 登记什么 | 干什么 |
|----------|--------|
| 全部符号与量纲 | 进符号表（成文期直接搬） |
| 题面约束 vs 引入约束 | 分列；引入的进假设清单 |
| 参数取值来源 | 题面给的 / 文献的 / 造假设的，分列注明 |
| 可视化点 | 这问最终该出什么图（先想好，求解时一并出） |

**降级（禁止卡死）：**

| 场景 | 做法 |
|------|------|
| 数据是文本/图像描述型 | 转量化（编码/打分/词频），记转换规则 |
| 纯机理题无数据 | 参数按题面 + 常识假设，列假设清单 |
| 数据太多（百万行） | 抽样探查 + 全量求解或增量计算，禁止「数据大就不做」 |
| 问的输出是「证明/说明」型 | 也必须给定量支撑（算例/反例/数值对比），禁止纯文字 |

### 4.2 求解实现（硬 · 真出数）

**每问三件套不得空窗**（对齐 `modeling-value.md` §2.1）：

| 类型 | 必须做的动作（有入口就做） | 无入口才可 N/A |
|------|--------------------------|----------------|
| **主模型求解** | 编码 → 运行 → 结果落盘（数值表/csv）；报错就修到通 | 题面无定量要求（罕见，须写明） |
| **独立验证证据** | ≥1 项，从菜单选：第二模型 / 解析特例 / 守恒关系 / KKT-对偶 / 约束残差 / naive 基线 / 小规模穷举 / 留出验证-回测 / 外部数据对照 / 数值收敛阶 / 极限行为（细则与「两模型接近 ≠ 稳健」纪律见 `result-check.md` §三）；偏差写进正文 | 该问为纯推导证明型 |
| **图** | 至少一张真数据图（结果图/流程图/拟合图按问选型，`plot-spec.md`） | 该问输出是纯方案且已有前问图覆盖（记原因） |

| 硬禁 | 说明 |
|------|------|
| **连问空窗** | 连续两问只写公式没跑数 → 违规偏科；下一问先补求解 |
| **假进度** | 草稿写「求解得到最优解」但 `结果/` 里没有对应文件 |
| **只建不检** | 主模型出了数就当全完；单问最低验证不做、全文检验（跨情景/稳健性）堆到最后一小时 |

**勾完 = 有真实结果的落盘 + 数字进草稿 + 图引用在正文**，不是「代码写完了」。

### 4.2.2 中间结果当线索（硬）

跑出的中间量是下一问/下一步的钥匙：拟合出的参数进下一问的输入、聚类出的簇标签可当分组约束、灵敏度最敏感的参数值得在假设里单独交代。**回包里新出现的 id/url/token 进清单** 的等价物：**任何被后问引用的结果，必须在 `进度.md` 里登记「q{i} → 供 q{j} 用 → 文件名」。**

### 4.3 结果落盘规范

```
结果/
  q1/result_q1.csv      ← 机器可读结果（数值表）
  q1/summary_q1.md      ← 该问结果的一句话结论 + 关键数字（成文直接抄）
  q1/figs/fig_q1_1.png  ← 真数据图（与图题对应）
  q2/...
```

- 每个数字要能溯源：论文里写「最优目标值 1 284.6」，`结果/q1/` 里必须找得到它
- `summary_q1.md` 是「成文期数字唯一来源」——正文与摘要的数字从这里抄，禁止凭记忆写数
- 图命名与图题编号一致（`fig_q1_1` ↔ 图 1）

### 4.4 本问「本轮完成」= 换问下限

1. §4.0 那几行已写
2. 主模型公式化（符号进表）
3. **真实运行出数**并落盘（无洞不写空结果）
4. 独立验证证据 ≥1 项（菜单见 §4.2）或 N/A + 原因
5. 至少一张真数据图，图题与内容一致
6. 求解正文进草稿（含数字与图引用）
7. 中间结果被后问依赖的，已在 `进度.md` 登记
8. 不耗在死路上：卡点已记 + 已换过一条路线

**必须切线：** 该问与题目要求无法闭环（数据根本不存在且不可假设）→ 记卡点、降级算例、写边界，换下一问，不提问停工。

## 5. 检验与成文（Phase 4～5 要点）

检验与成文的探针密度、摘要 8 要素、图表规范、参考文献：分别只认 `result-check.md`、`abstract-writing.md`、`plot-spec.md`、`paper-template.md` 与 `rules/paper-format.md`。本文件只钉节奏：

| 节奏 | 规则 |
|------|------|
| **两级检验** | **单问收口前（轻量，立刻做）**：正确性 sanity 三连（量级/方向/边界）+ 独立验证证据 + 结果重算核对，不挡推进；**全文检验（Phase 4 统一）**：跨情景灵敏度、稳健性（子样本/扰动重跑）、基线对比、模型对比、汇总图表与检验节成文 |
| 摘要何时写 | 正文成形后写；但**打磨优先级最高**（评委先读摘要）；至少两轮迭代 |
| 正文顺序 | 问题重述 → 问题分析（含每问思路图/流程图）→ 模型假设（编号+理由）→ 符号说明（表）→ 分问建模与求解 → 检验 → 评价与推广 |
| 附录 | 核心代码（真实运行版）+ 关键数据表说明；代码与正文结果一一对应 |
| 数字一致性 | 摘要 = 正文 = 图表 = `结果/` 文件，四处同源（§4.3），终检逐处核 |

## 7. 一句话

先判模式：**给题就做题**。拆题落 `进度.md`（逐问输入→候选模型粗路线 + 数据摸底 + 口径三级登记）→ **两级设计：粗路线一次做完，详细建模只属当前问** → **一问闭环：形式化 → 建模 → 编码真实出数 → 落盘 → 图 → 独立验证证据 → 进草稿 → 才换下一问** → 两级检验（单问最低验证 / Phase 4 全文检验）→ 摘要（最高优先打磨，必含每问数字）→ 正文整合 → 反造假红线逐条过 → 提交包。
**节奏口令：** 一问闭环出真数，先出数后成文，卡点记档换路线。本文件只防「只出思路不出数」的假进度，**不砍**模型深度、路线宽度与现场变通。
