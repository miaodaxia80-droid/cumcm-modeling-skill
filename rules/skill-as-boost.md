# skill 与自身能力并用（永久）

> 用户明确：不要靠 `/skill` 才干活；不要被 skill 限制死；**原始自身能力 + skill 都要用**。

> **一句话（最高优先级）：知识也好，skill 也好，rules 也好，只能增强你，不能限制你的思维与能力上限；灵活运用。**

## 定位

| 层 | 是什么 | 作用 |
|----|--------|------|
| **自身** | 数学与建模判断力、代码能力、会话上下文、现场证据 | 主决策与执行，永远在线；**思维与能力不被任何文档封顶** |
| **skill / 知识库 / rules 条文** | 方法论、清单、纪律、模板 | **增强包与质量闸门**，不是能力天花板 |

- skill / 知识库 = 加速与补全，不是「没写就不能做」
- **合并、删重、精简文档 = 去摩擦，不是砍能力**；条文变短后仍须会建模、敢假设、会变通
- 没有写到的题型 / 新方法 / 新工具 → **照样想、照样建、照样算**
- 文档与现场不符（题目比模板特殊）→ **以现场证据和自身判断为准**
- 与交付纪律（论文格式、任务目录）冲突时 → 交付以纪律为准；**建模思路与技术深度不被纪律写成「只能用清单点名的模型」**

## 纪律 vs 能力（分清）

| 该硬（质量/交付） | 不该硬（能力/发展） |
|------------------|---------------------|
| 数字必须真实可溯源、附录代码必须真跑通 | 「短表没这个模型所以不能用」 |
| 摘要必含每问数字、格式只认 paper-format | 「流程没写到这种建模方式所以不能建」 |
| 任务目录、进度.md 闸 | 「模板没有的章节不能写」 |

## 平时怎么用

1. 做题语境 → **自行**用 skill/知识库有用段落，不必等 `/skill`
2. 先自身判断题型与路线；细节再查模块
3. 不机械只跑 Phase 表；题目里的新形态照样处理
4. 禁止「没开 skill / 表上没有所以不能做」

## 知识库运营

- 读：有用就用；没有就靠自身继续。拆题默认 **先短表、再开需要的模块**（见 `iter-gain.md`）
- 写 / 单篇肥了怎么拆：只认 `iter-gain.md`
- 整理记忆时：**可融合、可删废，不可借整理把能力写窄**

## 一句话

**自己能做题是本分；文档用来变强、用来避坑；谁也不封你的上限。**
