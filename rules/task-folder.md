# 任务根文件夹（永久强制 · 任务根格式）

> 叫我做数模任务时，**按「{题号}_数模竞赛」那种格式**建任务根目录；分夹清楚、条例清晰。
> 位置默认顺序：**用户指定路径 > 当前工作区 > 桌面新建**；桌面只能是显式偏好，不是硬规则。
> **禁止**把论文/代码/结果直接堆所选根目录；**禁止**只丢一个扁平文件夹就把所有东西塞进去凑合。
> 可直接跑本 skill 的 `scripts/init_task.py` 代建（结构与本文件一致）。

---

## 1. 标准目录格式（永久模板）

任务根命名：`{题号/主题}_数模竞赛`（如 `C题_垃圾清运优化_数模竞赛`）。

**开新任务时必须一起建齐：**

```
{任务名}_数模竞赛\
  README.md          ← 任务说明、目录结构、进度、续跑说明
  题目/              ← 题面原文（PDF/截图/文本）+ 附件数据原件（只读，不改）
  进度.md            ← 状态闸（见 §1.1；必须起手落盘）
  数据/              ← 清洗后的中间数据集（原件留题目/，衍生表放这里）
  代码/              ← 全部代码 + requirements.txt + 代码/README.md（运行顺序）
  结果/              ← q{i}/result_q{i}.csv + summary_q{i}.md + figs/（见 contest-workflow §4.3）
  论文/              ← 草稿.md + 终稿源文件 + 图表
  提交/              ← PDF + MD5 + 支撑材料 zip + 提交清单.md
```

**对照范例（必须对齐）：**

| 子目录 | 放什么 | 不放什么 |
|--------|--------|----------|
| `题目/` | 题面原文（PDF/文字）、原始附件（Excel/CSV/说明）**只读不改** | 清洗后的版本（去 `数据/`）；脚本 |
| `进度.md` | 拆题清单、路线表、每问状态（pending/doing/收口/卡点）、结果文件登记、卡点记录 | 正文内容；草稿 |
| `数据/` | 清洗/加工后的数据集（`clean_*.csv` 等）+ 处理脚本说明 | 题目原件；结果 |
| `代码/` | 分问脚本（`q1_*.py`）+ 公共模块 + `requirements.txt` + `README.md`（运行顺序一句话一步） | 论文草稿；一次性废弃脚本（随做随清） |
| `结果/` | `q{i}/result_q{i}.csv` + `q{i}/summary_q{i}.md` + `q{i}/figs/` | 代码；论文 |
| `论文/` | `草稿.md` → 终稿（LaTeX 源或 Word）+ 编译 PDF | 结果文件；代码 |
| `提交/` | 最终 PDF、MD5、支撑材料 zip、提交清单.md | 中间稿 |

### 1.1 题目原件 vs 清洗数据（强制分清）

| 内容 | 正确路径 |
|------|----------|
| 题面 PDF/截图、原始附件 | `题目/`（只读） |
| 清洗、合并、变换后的数据 | `数据/`（可再生成：脚本在 `代码/`） |
| 运行产出的数值结果与图 | `结果/`（不是 `数据/`） |

**禁止：** 直接改写 `题目/` 里的原件；把结果图塞进 `数据/`。

## 2. 硬规则

1. **一任务一根目录**，起手就建，再开始产出。
2. **七件齐**：`README + 题目 + 进度.md + 数据 + 代码 + 结果 + 论文`（提交包在 Phase 6 建）——条例清晰，不混放。
3. 结果路径固定：`{任务根}/结果/`；代码里输出路径必须指向这里。
4. 清洗数据路径固定：`{任务根}/数据/`；题目原件只在 `题目/`。
5. 论文路径固定：`{任务根}/论文/`。
6. 续跑、增做、改稿 → **仍进同一任务根**，不另开散文件。
7. 所选根目录 **禁止** 再落论文 `.md/.docx/.pdf`、结果 csv、零散 py/js（都进对应子夹）。
8. 用户已指定路径时以用户为准；未指定 → 当前工作区，工作区不适合落盘（只读/临时）→ 桌面。
9. **开新任务必须落 `进度.md`**：拆题清单 + 粗路线表 + 口径列 + 状态列。README.md 钉一行「续跑先读 进度.md」。条文只在 `contest-workflow`。

### 2.1 进度.md 最小模板

```
# {题号} 数模进度
## 模式与口径
（比赛/练习；每问口径：official / assumption / synthetic-demo）
## 拆题（粗路线）
| 问 | 要什么 | 输入 | 输出 | 依赖 | 候选模型 | 口径 | 状态 |
|----|--------|------|------|------|----------|------|------|
| q1 | … | … | … | … | … | official | pending/doing/收口/卡点 |
## 数据摸底
（表名/行数/列/缺失一眼登记）
## 约束清单
（题面逐条编号 + 常识隐含，各标来源）
## 假设清单
| # | 假设 | 理由 | 影响哪问 |
## 结果登记
| 文件 | 供谁用 |
|------|--------|
## 卡点记录
（问题 + 换过什么路线 + 结论）
```

## 3. 用户说「清理」时（操作）

| 情形 | 动作 |
|------|------|
| 有终稿 PDF | 全保留：`题目/数据/代码/结果/论文/提交` + `进度.md`（可归档） |
| 只有草稿/中间产物 | 删 `提交/`、终稿重复副本；保留 `结果/`、`代码/`、`数据/`、`题目/`、`进度.md` |
| 纯废稿（用户明说不要了） | 整根删掉 |
| **禁止** | 误删 `结果/`（唯一证据源）与 `题目/` 原件；把非任务目录当任务根删 |

## 4. 自检（写文件 / 交稿 / 开新任务前）

- [ ] 是否已有 `{任务}_数模竞赛\` 任务根（用户指定路径/工作区/桌面）？
- [ ] 七件是否齐？`进度.md` 是否起手落盘且状态最新？
- [ ] 题目原件是否只在 `题目/`（未被改写）？
- [ ] 清洗数据是否只在 `数据/`、结果只在 `结果/`、代码只在 `代码/`？
- [ ] 论文数字能否溯源到 `结果/q*/summary_q*.md`？
- [ ] 有没有东西误落根目录？有则 **移入对应子夹**（不是删掉糊弄）
- [ ] 收口前跑过 `scripts/verify_task.py` 吗？FAIL 清零了吗？

---

**一句话：** 开新任务 = `README + 题目(只读) + 进度.md + 数据 + 代码 + 结果 + 论文`；续跑先读 `进度.md`；结果文件是论文数字的唯一来源，永不删。
