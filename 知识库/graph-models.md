# 图论与网络（graph-models）

> 对得上：路径、配送、选址、覆盖、连接、匹配、流量、网络优化。
> 主线：建图（节点边表）→ 选算法 → 程序算出最优方案 → 可视化。

## 一、建模套路

```
1. 抽象：什么当节点（站点/客户/路口）、什么当边（可达/服务关系）、边权（距离/时间/成本）
2. 距离矩阵用程序算（经纬度 haversine；网格曼哈顿），禁止手抄
3. 选算法（下表）→ 求解 → 方案表 + 路线图
4. 约束变体：容量限制 → 加入容量约束的 MIP 或分组；时间窗 → 有向约束或罚函数
```

## 二、算法速查

| 问题 | 算法 | 实现 |
|------|------|------|
| 点对最短路 | Dijkstra（非负权） | networkx.shortest_path_length |
| 全源最短路 | Floyd-Warshall / Johnson | nx.all_pairs_shortest_path_length |
| 最小连接成本 | 最小生成树（Kruskal/Prim） | nx.minimum_spanning_tree |
| 最大流量 | Ford-Fulkerson / Edmonds-Karp | nx.maximum_flow |
| 关键节点 | 中心性（度/接近/中介） | nx.degree_centrality 等 |
| 设施选址（服务 k 个点的最小总成本） | P-中值 | MIP 或启发式 |
| 覆盖问题（最少设点覆盖所有需求） | 集合覆盖 MIP | pulp |
| 两两最优配对 | 二分图最大权匹配 | scipy.optimize.linear_sum_assignment（匈牙利） |
| 旅行商/路径 | TSP/VRP | MIP 小规模；大规模用启发式（2-opt、遗传） |
| 生态/影响力 | PageRank / 特征向量中心度 | nx.pagerank |

## 三、常见题型组合拳

| 题型 | 组合 |
|------|------|
| 应急设施选址 | 覆盖半径约束 MIP + 加权（人口/需求权重）+ 多阶段（先临时后永久） |
| 配送路径 | VRP：MIP 小规模 / 节约算法 + 2-opt 改进；时间窗 → 违约惩罚项进目标 |
| 网络鲁棒性 | 删点/删边看连通性变化（最大连通子图占比）→ 稳健性结论 |
| 交通分配 | 最短路分配 → 用户均衡（简化：迭代加载） |
| 影响力/重要节点 | 多中心度对比 + 鲁棒性删点实验 |

## 四、复杂度闸（规模大时）

- n ≤ 几千节点：networkx 直算
- TSP 上百节点：精确解跑不动 → 启发式（贪心 + 2-opt 局部搜索），报「启发式解 vs 下界（MST 或松弛）」的 gap
- 边太密：先按需求裁剪（k 近邻图）

## 五、常见坑（假点）

- 距离矩阵手算且没程序复核
- 忘了有向/无向、对称/不对称的区分
- 覆盖类问题没处理需求权重（所有人平等 vs 人口加权）
- 只给最优路径值，没画路线图（评委看不懂方案）
- 把「连通」当成「边存在」（要考虑容量/时间维）

## 六、论文里写什么

1. 图抽象定义（节点、边、权含义一句）
2. 模型（数学形式：目标 + 约束，或算法流程图）
3. **方案结果**（选址点/路径序列/分配表，来自 `结果/q*`）
4. 路线图/网络图（matplotlib 或 networkx 布局，节点标号清晰）
5. 成本对照（方案成本 vs 现状/基线）

**一句话：** 节点边先抽象、距离程序算、算法对号入座、大图用启发式给 gap、方案必须画图说话。
