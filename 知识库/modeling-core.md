# 通用建模核心（modeling-core）

> **每问开算前必过本篇**：先形式化，再查 `打穿短表.md` 选模块。短表管「哪类题用哪招」，本篇管「这个系统到底该建成什么数学结构」。
> 它是把「算法分诊」升级成「数学建模」的那一层；表上没有的题照样能靠它起步。

## 一、形式化链条（每问走一遍，写进草稿 3~5 行）

```
现实对象 → 系统边界（研究什么、忽略什么）
        → 变量分类：状态 / 决策 / 观测 / 参数 / 外生输入
        → 目标与约束（要优化什么、什么不能违）
        → 数据生成机制（这些数据是怎么产生的、观测到的是全部吗）
        → 假设（每条：内容 + 理由 + 可验证方式）
        → 数学形式（方程 / 规划 / 概率模型 / 图结构）
        → 求解与验证（算法 + 独立验证证据，result-check §三）
        → 不确定性（参数/观测/结构，uncertainty-and-identifiability.md）
        → 可操作结论（回答题面问句，不超证据）
```

## 二、五个先决判断（选模型前必答）

| 判断 | 选项 | 对选型的影响 |
|------|------|--------------|
| **问题类型** | 描述 / 预测 / 解释（归因）/ 控制 / 决策 | 预测→`predict`；解释→`stat`（因果≠相关）；控制→`control`；决策→`op` |
| **数据类型** | 观测数据 / 实验数据 / 题设参数 | 观测数据只能谈相关，因果结论要额外论证；题设参数可直接进模型 |
| **变量关系** | 因果 / 相关 / 纯约束 | 相关模型不能写「A 导致 B」；约束关系进规划不该进回归 |
| **输出形态** | 点值 / 区间 / 排序 / 方案 / 分布 / 证明 | 要区间/分布 → 必须做不确定性量化，点模型不够 |
| **外推范围** | 内插 / 外推 / 政策反事实 | 外推与反事实必须交代「假设条件不变」，并用回测支撑 |

## 三、可识别性快检（数据撑得起这些参数吗）

| 信号 | 判定 | 处置 |
|------|------|------|
| 自由度 < 待估参数数 | 不可识别 | 减参数 / 加先验/正则（`numerical-models.md`）/ 降模型 |
| 两参数总是同向变、单独动谁拟合都一样 | 参数强相关、近似不可分 | 参数化重构（合并为比值/组合量）或固定其一并声明 |
| 换初值拟合结果大变 | 目标函数病态/多峰 | 多起点 + 报告参数 CI（profile/bootstrap，`uncertainty`篇） |
| 拟合完美但外推崩 | 过拟合/结构错 | 交叉验证 + 简单基线对照，回 `result-check.md` §三 |

**一句话：样本撑不起参数就别硬估——降维、正则、或声明为假设。**

## 四、最小模型说明表（每问一张，进 `进度.md`，成文可直接搬）

| 项 | 内容 |
|---|---|
| 决策目标 | 这问到底要预测、解释、控制还是优化什么 |
| 输入 | 官方数据 / 前问输出 / 外部数据 / 假设参数（各标来源） |
| 输出 | 点值、区间、排序、方案、策略或证明 |
| 状态/变量 | 哪些是状态、决策、观测、潜变量（含单位量纲） |
| 约束 | 物理、资源、逻辑、统计、边界条件 |
| 假设 | 内容、依据、可验证方式、影响哪个结论 |
| 可识别性 | 现有数据能不能区分这些参数/模型（§三结论） |
| 验证证据 | 用什么独立证据证伪错误模型（`result-check.md` §三菜单选一项） |
| 不确定性 | 参数 / 观测 / 结构不确定性分别怎么处理 |

## 五、复杂度增益闸（用复杂模型前必答）

上复杂模型（神经网络/大 MIP/高维非参数）前先问：

1. **基线赢了吗？** naive/线性/贪心基线先跑，复杂模型必须可验证地更好（`result-check.md` §三基线）
2. **数据撑得住吗？** 样本量/自由度 vs 参数量（§三）
3. **可解释吗？** 评委要的「结果正确性」能不能用简单语言交代；不可解释模型配 SHAP/部分依赖图（`ml-models.md`）
4. **多出的复杂度回答了题目哪个问句？** 答不上 → 用简单模型

**禁止**：基线没跑就上复杂模型；「显得高级」当选型理由。

## 六、常见坑（假点）

- 跳过形式化直接按问句关键词套模型 → 建出来的模型答非所问（这是「算法分诊」不是建模）
- 把相关当因果写进结论（「X 增加 导致 Y 增长」但只有观测数据）
- 模型里变量比数据多 → 参数不可识别，拟合数字无意义
- 输出要「方案」却建了纯预测模型（预测完没接优化/决策层）
- 假设写了「忽略 X」，求解时 X 又进了模型（假设与求解打架，`SKILL.md` 红线 5）

## 七、与其它文件的关系

| 文件 | 分工 |
|------|------|
| `rules/contest-workflow.md` | 本篇用在 §1.2 单问详细设计与 §4.0 进问三问；流程节奏它管 |
| `打穿短表.md` | 本篇输出（问题类型+结构）→ 再查短表选具体模块；短表是索引不是上限 |
| `uncertainty-and-identifiability.md` | §三的深化：CI、bootstrap、Sobol、profile likelihood |
| `result-check.md` | 表里「验证证据」从它菜单选 |

**一句话：** 边界→变量→机制→形式→验证→不确定性，六步想清再写码；可识别性快检挡住「数据撑不起的参数」，复杂度增益闸挡住「炫技模型」。
